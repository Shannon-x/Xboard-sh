# 自选套餐：数据库分析与发布说明

生产数据库仍为原套餐配置。代码合并与启用销售配置是两个步骤；价格示例用于评审，未作为正式销售价格写入生产。

## 数据库现状（2026-09-10，只读检查）

| ID | 套餐 | GB/月 | 设备 | Mbps | 元/月 | 当时未到期用户 |
|---|---|---:|---:|---:|---:|---:|

| 30 | 轻享版 | 500 | 3 | 400 | 6.6 | 637 |
| 16 | 悦享版 | 1000 | 5 | 500 | 9.9 | 579 |
| 31 | 畅享版 | 2000 | 8 | 800 | 19 | 70 |

四项权限组和每月 1 日重置规则相同，关联用户合计 3003 个，当时未到期 1879 个。适合新增一个自选套餐替代销售入口，保留原 ID、订单、用户规格、有效期及续费规则。这样显示套餐从 34 个减至 31 个；历史记录不删除。

权限组 17 的 32—35 是已隐藏的不限时流量包，不能与周期套餐合并，其 `reset_traffic_method=3` 表示每年 1 月 1 日重置，与“不限时用完为止”的文案需要另行核对。多数静态家宽虽然同为 250GB、5 台、500Mbps、20 元，但权限组及席位不同，应保留线路区别，用分类网格改善选择。

套餐 43 的实际规格为 550GB / 800Mbps，文案仍写 420GB / 600Mbps。新自选套餐可使用 `{{transfer}}`、`{{devices}}`、`{{speed}}`，避免文案与实际规格分离。

## 已实现规则

- 管理端：每项可独立设置固定、范围选择或指定选项。固定项使用套餐原规格，不收增购费；范围设最大值和步长；指定选项设可售容量或规格列表。旧配置中的最大值等于基础值仍按固定处理。
- 全部固定：用户端不显示规格选择、不调用新报价接口；后端保留原周期价格、金额转换、购买和续费流程，不产生自选快照，也不限制原支付方式。固定设备和速度保留原值，包括 null/0 表示不限；开放自选的项目必须有有限正整数基础值和上限。
- 用户端：分类网格比较套餐，范围用滑块、指定选项用容量按钮、固定项仅显示；展示基础价、增购价格和优惠前合计。付款周期卡片随选择更新；折扣标签按真实价格计算。
- 价格：套餐 `prices` 仍是元；规格 `price_per_step` 与报价/订单金额是分。管理表单显示元并转换为分。
- 单项加价 = 增购步数 × 每步加价 × 当前周期基础价 / 月付基础价。每项四舍五入至分后相加。不限时套餐使用一次性基础价为参考。保留原套餐周期折扣。
- 服务端报价 `/api/v1/guest/plan/quote`、`/api/v1/user/plan/quote`；下单只接受规格并重新核价。可传 `expected_amount` 防止报价至付款前价格变化。
- 订单 `plan_snapshot` 固化规格、名称、权限组、重置规则及报价明细；付款开通使用快照，不随管理员后来修改基础规格而改变。
- 用户 `plan_options` 保存当前所购规格；省略规格续费时恢复已有选择。同一套餐改变任一规格按套餐变更处理，沿用旧套餐剩余价值折抵，从付款时重开新周期。
- 流量重置不修改规格、不重复收取设备和速度费用，也不推迟已有重置时间。
- 开放自选的项目不接受 null、0、负数、小数、未知字段或范围步长不符的值。指定选项必须包含基础值、递增且不重复，最多 100 项；服务端拒绝未列出的规格，不能只依赖前端按钮。可选规格绝对上限为流量 1,000,000GB、设备 100 台、速度 10,000Mbps，最高订单 1,000,000 元，保存时校验最贵组合。固定规格不能被客户端改写。
- 自选套餐禁止强制覆盖全体用户规格；不能关闭配置或缩小范围使已有自选用户或待处理订单开通后无法续费。
- 中间件对两个报价端点增加 Xboard 专用加密路径映射。
- 新前端访问用户套餐接口时传 `include_customization=1` 获取基础规格和定价规则。旧客户端不传该参数时，当前自选订阅按已购规格和对应价格展示在旧字段中，省略 options 续费仍保持原规格，保证显示价格与下单价格一致。新前端连接旧后端时，缺少 customization 字段就沿用原购买流程。
- 当前挂载的 StripeSubscription / PaypalSubscription 自动续订插件没有规格快照传递。自选订单只展示可用的单次支付方式，后端也拒绝这两个自动续订通道；固定套餐不受影响。后续若支持自动续订，须同时保存初始规格、处理套餐变化时旧自动订阅的终止及续费核价。

## 增值节点组（2026-09-11）

在自选规格之上，套餐可把节点按**权限组**分档出售。零新表、零新列，不改 `user.group_id` 语义。

- 一个增值等级 = 一个 ServerGroup。管理员把 10x 等节点加进对应权限组即完成打标签（节点编辑器已有分组多选）；套餐里对每个非基础组三选一：`不提供`（默认）/ `包含`（随套餐赠送）/ `可选购`（按月加价，分）。基础权限组不能再作为增值组出售。
- 配置落在 `plan.customization.addon_groups = { "<组id>": {mode, price} }`，与三项资源规则并列。配了任何增值组的套餐即视为自选套餐：走快照、拒绝自动续订通道；但只含 `包含` 组且资源全固定时，金额与原周期价一致。
- 计价与资源加价同一规则：`可选购` 组月价 × 当前周期基础价 / 月付基础价，年付折扣自动传导；流量重置包不重复收费。保存时把全部可选购组一并计入最贵组合校验。
- 客户侧存两份：`plan_options.addon_groups` 是勾选的可选购组（续费/重置原样带回重新报价）；`plan_options.granted_groups` 是 `包含 ∪ 已购` 的生效集合。两个键都不存在 = 旧用户或未配置增值组的套餐，行为与本功能上线前逐字相同。
- 节点可见性 `ServerService::getAvailableServers` 按 `基础组 ∪ granted_groups` 取并集；**节点端拉名单 `getAvailableUsers` 同样按并集**——没买的用户不会出现在 10x 节点的名单里，手工拼配置也连不上。
- 同步：`plan_options` 变更触发 `NodeUserSyncJob`，先对失去的组推 remove，再由 `notifyUserChanged` 对 `基础组 ∪ granted_groups` 的节点重推；用户删除时增值节点名单也一并清理。
- 同套餐只多勾/少勾一个增值组也按套餐变更处理（旧周期折抵、新周期从付款时重开）。管理员不能撤下已有用户或待处理订单已购的可选购组。
- `PlanResource` 内嵌组名与节点数供前端展示（用户端没有分组接口），不下发任何节点名称/地址；需要 `preserveKeys`，否则 JsonResource 会把数字键的组映射重排成列表。
- 用户端：套餐页「增值节点」区块，包含的只读显示，可选购的是一个开关 + `+¥X/月`；节点页对已订阅但未购买的组展示锁定卡片 + 「升级解锁」直达套餐页。下单前经 `selectionOf()` 剔除派生键 `granted_groups`。
- 中间件无需改动：不新增用户/guest 路径。**部署注意**：本地中间件克隆若落后于 `Shannon-x/sufe-middleware-rs` 主分支，`plan/quote` 路径映射可能缺失，须先 `git pull` 再构建。

## 价格示例（待确认）

### 固定设备和速度，只指定流量包容量

例如基础套餐包含 100GB、2 台设备、100Mbps，在管理端将设备数和速度设为“固定”，流量设为“指定选项”并填写 `100, 250, 500`。每 100GB 超出部分加 0.60 元，选择 250GB 时加价 0.90 元。列表的容量不必整除计价单位，加价按比例计算并四舍五入到分。

```json
{
  "transfer_enable": {"mode": "choices", "choices": [100, 250, 500], "max": 500, "step": 100, "price_per_step": 60},
  "device_limit": {"mode": "fixed"},
  "speed_limit": {"mode": "fixed"}
}
```

上面是 customization 字段的值。不限时流量套餐单独设置 onetime 基础价格、重置方式“不重置”；周期套餐也可以使用容量选项。原 reset_price 仍表示重置当前订阅全部流量，保留原语义，不作为额外叠加流量包。

三项均设 `{"mode":"fixed"}` 或关闭自选配置，即恢复原套餐定价。已有不同规格用户或待处理订单时不能直接改成不兼容的固定值；应保留旧套餐续费、新建固定套餐销售。

### 权限组 17 的范围计价示例

`group-17.example.json` 示例：3 元/月含 100GB、2 台设备、100Mbps；每增加 100GB 加 0.60 元、每增加一台加 0.50 元、每增加 100Mbps 加 0.20 元。最高 2000GB、8 台、800Mbps。

| 示例选择 | 新月价 | 原月价 |
|---|---:|---:|
| 100GB / 2台 / 100Mbps | 3.00 | 3.00（原为66GB） |
| 500GB / 3台 / 400Mbps | 6.50 | 6.60 |
| 1000GB / 5台 / 500Mbps | 10.70 | 9.90 |
| 2000GB / 8台 / 800Mbps | 18.80 | 19.00 |

这是一组便于评审的起始参数，正式倍率需结合线路成本决定；无单一线性加价公式能精确还原现有四档的全部价格。存量用户继续使用原套餐，避免强制改价。

## 合并与发布

先发布兼容新字段的后端和管理员资源，并执行迁移，再更新中间件和用户前端。两个报价路由也可通过中间件 `EXTRA_OBFUSCATED_PATHS` 临时加入。不要在未执行迁移的数据库上启动新后端。

下面的默认命令只预览，不写库：

```bash
php artisan plan:consolidate --source=16 --source=29 --source=30 --source=31 --config=docs/configurable-plans/group-17.example.json
```

加 `--apply` 创建隐藏草稿；加 `--apply --publish` 在同一事务内创建可售自选套餐并隐藏原四项，保留其续费开关。命令校验权限组、重置方式、计费类型，拒绝重复名称，禁止合并不同线路权益。正式执行前保留数据库备份和原 show/sell 值。

如已先创建隐藏草稿，不要重跑创建命令，使用管理端发布已有草稿并隐藏旧销售入口。新套餐有订单后，不得通过删除字段或回滚代码恢复；先停止新销售并继续提供现有用户续费和订单处理。

管理员真实源码在 `Shannon-x/XBoard-admin`。构建嵌入式资源时，在它的干净构建副本中执行本仓库 `scripts/patch-admin.sh`，再 `npm ci && npm run build`，将 dist 同步到后端 `public/assets/admin`。后端的 sync-admin 工作流会从管理员主分支重新构建，因此需协调两仓分支发布。

## 流量加购包（traffic_topup）

- 周期 `traffic_topup`、订单类型 `5`。顶层字段 `topup_gb`（GB）。走现有 `plan/quote → order/save → 回调 → open` 链路。
- 单价：站点设置 `traffic_topup_price_per_gb`（分/GB，0 = 不开放）、`traffic_topup_min_gb/max_gb/presets`；
  套餐 `customization.traffic_topup = {mode: inherit|off|custom, price_per_gb?, min_gb?, max_gb?}` 覆盖；
  增值组规则 `topup_price_per_gb` 给持有该组的用户每 GB 加价（同一套餐买了 10x 组的人加购更贵）。
- 开通：`transfer_enable += N GB` 且 `transfer_topup += N GB`（记账列）。
- **不变量**：任何把 u/d 清零的动作（月度重置、重置包、提前周期、换套餐、新购、管理员手动重置）
  由 `TrafficResetService::performReset` / `AdvanceCycleService` 统一 `transfer_enable -= transfer_topup; transfer_topup = 0`。
  普通续费只叠时长、周期继续，加购保留。`hasChangedOptions` 与折抵按 `transfer_enable − transfer_topup` 比较。
- `getSubscribe` 新增 `traffic_topup`（规则 + `active_bytes` + `valid_until`）与 `addon_groups`；`PlanResource` 新增 `traffic_topup` 顶层键。旧前端不读这些键。

## 增值组「包含」的实时语义与管理员授予

- 用户此刻生效的增值组 = 套餐当前 `included` 组（按 `plan_id` 查 60s 缓存表，PlanObserver 保存即失效并通知相关组节点重拉）
  ∪ `plan_options.addon_groups`（已购 optional，快照）∪ `v2_user.admin_group_ids`（管理员手动授予，与套餐无关、不参与报价、换套餐保留）。
- `plan_options.granted_groups` 只作兼容字段：开通时仍写入，热路径不读；`getSubscribe?include_addon_groups=1` 用生效集合覆盖它。
- 节点端名单三条索引分支：`group_id`、`plan_id`（包含组）、JSON（optional / 授予组，仅在相关组时才发）。
- 管理端：`user/update` 接受 `admin_group_ids`；用户筛选虚拟字段 `addon_group`。
