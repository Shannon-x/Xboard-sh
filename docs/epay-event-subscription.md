# 易支付 V2 事件消息订阅（交易投诉 / 订单退款）

牛牛支付等易支付 V2 网关的商户后台有「事件消息订阅设置」：发生交易投诉、订单退款时，网关把事件推送到订阅 URL，
签名同 V2 异步通知（平台公钥 SHA256withRSA）。只支持 V2 RSA 方式的支付配置。

## 订阅地址

```
https://<站点域名>/api/v1/guest/payment/notify/EPay/<支付配置 uuid>/event
```

- uuid 是后台「支付配置」里那条 V2 EPay 配置的 uuid（与它的支付回调地址同一个）。停用的配置也收，旧单的投诉退款照样处理。
- 挂在支付回调前缀下，sufe-middleware-rs 的回调白名单 `/api/v1/guest/payment/notify/*` 直接透传，不用改中间件配置。
- 事件两个都勾：交易投诉、订单退款。
- GET / POST 表单 / POST JSON 都收；验签通过回 `success`，验签不过或 uuid 不对回 422 `verify error`。限流每 IP 每分钟 60 次。

## 收到后做什么

推送只当「该去查了」的信号，不当事实，处理放进队列（`HandleEpayEventJob`，default 队列），接收端先回 success：

| 事件 | 处理 |
| --- | --- |
| 订单退款 | 按网关交易号立即回查（`RefundWatchService::recheckByCallbackNo`），网关两次查单都说退了才封号、收回套餐、作废 / 扣回佣金，和日常回查同一套 |
| 交易投诉 | 立即拉一轮投诉列表（`EpayGatewayMonitor::complaints`，投诉告警和回查都在那里），并回查这笔；冻结只告警 |
| 只带商户单号 | 先向网关查出网关交易号再回查（商户单号可能是支付会话号） |
| 验签不过 | 记日志（只记字段名）、1 小时内告警一次，提前拉一次投诉列表；不按推送里的单号做任何事 |

额外告警：每个配置收到第一条退款 / 投诉推送时告诉一次「事件订阅已打通」（附字段名，便于核对推送格式）；
推送说退款但查单仍是已付、或本站找不到这笔单时各告警一次。同一笔同一类推送 10 分钟内只处理一次。
推送里可能有投诉人手机号，日志和告警只写字段名不写值。

网关文档没写推送字段，事件类型按 `event` / `event_type` / `notify_type` / `type` 等字段的值里有没有 refund / complain / 退款 / 投诉识别，
认不出时再看字段名；单号取 `trade_no` / `out_trade_no`，也会展开 `data` 之类的子对象或 JSON 串。

每 10 分钟的投诉轮询（`payment:epay-complaints`）和退款回查（`payment:refund-watch`）照旧运行，推送丢了也能兜住。

## 相关：回查时 V2 查出「未支付」

已付的单回查时 V2 网关返回状态 0（未支付）：不是退款状态，不处置，但第一次见到会告警，之后照旧每小时重查。以前这种情况只记作查询失败，不告诉人。
