# 支付通道拉取日报与告警

每次客户点「去支付」，面板向网关要收款链接。`App\Support\PaymentLinkStats` 按支付配置记下当天成功、失败次数，失败按网关原话归类（无可用通道、限国内IP、单笔限额、通道维护、单号重复、签名或配置错误、网关连不上、跳转地址不认、其他）。同一张单在支付会话里连点只算一次。

- 23:30 付款核验日报末尾追加「支付通道拉取」：每个通道成功 / 失败 / 失败率、已付笔数（套餐单 + 充值单）、转化率、近 7 天转化率，以及前几类失败原因和一条原话。
- `payment:link-health` 9:00–23:59 每 15 分钟：
  - 最近 60 分钟拉取 ≥5 次且失败 ≥50% → 告警；
  - 最近 2 小时（不含最近 10 分钟）拉成功 ≥6 次、一笔没付，而近 7 天转化 ≥20%（且近 7 天至少 20 次）→ 告警；
  - 同一通道同类告警 3 小时最多一次；停用的通道不告警。

跳转式网关（易支付 V2 jump、V1 submit）的「未适配到通道」「请使用国内IP」在客户浏览器打开付款页时才出现，面板这一步只拿到跳转地址，记成成功；这类故障靠「拉到链接没人付」那条告警发现。

数据在缓存（生产 Redis）：日计数 10 天、10 分钟桶 3 小时。缓存故障不影响下单。

部署：`plugins/` 在宿主机挂载，`plugins/Epay/Plugin.php` 要同步到宿主机，失败原因才会是网关原话；不同步时仍计数，原因记成「支付通道暂时不可用」归到「其他」。
